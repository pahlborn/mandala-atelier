Der erste Durchgang mit Xcode

Die Web-App als richtiges iPad-Programm auf das eigene Gerät bringen. Schritt für Schritt, für jemanden, der Xcode noch nie geöffnet hat.

Das hier kostet nichts. Das Apple Developer Program (99 € im Jahr) wird für diesen Durchgang nicht gebraucht. Eine gewöhnliche Apple-ID genügt. Die App läuft danach sieben Tage auf Ihrem iPad — genau lange genug, um zu sehen, ob es trägt.

Und darum geht es: nicht darum, fertig zu werden, sondern herauszufinden, ob der Weg überhaupt gangbar ist. Läuft die App im Flugmodus vollständig? Wie fühlt sich der Stift an? Was macht der Druckbogen? Am Ende dieser Seite steht ein Befundbogen — der ist das eigentliche Ergebnis.

Was Sie vorher brauchen

  • Der Mac. Der iMac mit M3 genügt vollauf.
  • Xcode mit angehaktem iOS-Baustein. watchOS, tvOS und visionOS sind nicht nötig; das Predictive-Code-Modell auch nicht.
  • Node. Falls noch nicht da: von nodejs.org die Fassung mit dem Zusatz LTS laden und das Installationsprogramm durchklicken.
  • Google Chrome — ja, wirklich. Warum, steht gleich in Schritt 4.
  • Ein Kabel und das iPad.

Teil A · Auf dem Mac vorbereiten

1

Das Terminal öffnen

Das ist das Fenster, in das man Befehle tippt. ⌘ + Leertaste drücken, Terminal eintippen, Enter.

Es erschreckt beim ersten Mal, ist aber harmlos: Sie können jeden Befehl von hier kopieren und einsetzen und dann Enter drücken. Nichts davon verändert etwas an Ihrem Mac außer in einem Ordner, den wir gleich anlegen.

2

Nachsehen, ob Node da ist

node --version

Kommt eine Zahl wie v22.11.0, ist alles gut. Kommt command not found, fehlt Node — dann von nodejs.org die LTS-Fassung installieren und dieses Fenster einmal schließen und neu öffnen.

3

Das Repository auf den Mac holen

cd ~/Documents
git clone https://github.com/pahlborn/mandala-atelier.git
cd mandala-atelier

cd heißt „geh in diesen Ordner“. Nach diesen drei Zeilen liegt das ganze Projekt in Dokumente → mandala-atelier, und das Terminal steht darin.

Falls git nicht gefunden wird: macOS fragt dann selbst, ob es die Entwicklerwerkzeuge nachladen soll — annehmen und warten. Xcode bringt sie ohnehin mit.

4

Die Hilfspakete holen

npm install

Holt, was die Werkzeuge des Projekts brauchen. Dauert ein paar Sekunden.

Hier braucht es Chrome. Der nächste Schritt zeichnet das App-Symbol in 1024 × 1024 — und dafür startet er im Hintergrund einen Browser. Gesucht wird nach Google Chrome oder Chromium in Programme. Safari genügt nicht. Ist keiner da, bricht Schritt 5 mit einer Meldung über einen fehlenden Browser ab — dann Chrome installieren und den Schritt wiederholen.
4b

Alles auf einmal nachprüfen

npm run mac

Geht die Liste von oben durch und sagt für jeden Punkt, ob er da ist: macOS, Node, git, Xcode, der iOS-Baustein, ein Browser fürs Symbol, ein angeschlossenes iPad, freier Platz. Zu jedem ✗ steht daneben, was zu tun ist.

Diesen Bericht darf man kopieren und weiterreichen — wer aus der Ferne hilft, sieht Ihren Mac ja nicht. Er enthält keine Namen, keine Gerätekennungen und keine Pfade aus Ihrem Benutzerordner; der Gerätename und die Seriennummer werden ausdrücklich weggelassen.

Es ändert nichts. Das Werkzeug liest nur nach und schreibt auf.

Teil B · Die App für den Rahmen vorbereiten

5

Den nativen Ordner erzeugen lassen

npm run nativ

Das legt nativ/mandala/ an und stellt alles hinein, was gebraucht wird: die App selbst, das Symbol ohne Alphakanal (mit Alphakanal würde Apple es ablehnen), die Konfiguration — und eine LIESMICH.md, in der die folgenden Schritte noch einmal stehen.

Für die zweite App hieße es npm run nativ:blatt. Fangen Sie mit einer an.

Was dabei nicht passiert: Der Code wird nicht umgeschrieben. Xcode übersetzt kein JavaScript — die Dateien ziehen um, mehr nicht. Die einzige Änderung: Die Registrierung des Service Workers fällt weg, weil im Bundle ohnehin alles auf dem Gerät liegt.

6

Die vier Befehle von Capacitor

cd nativ/mandala
npm install
npx cap add ios
npx cap sync
npx cap open ios

Beim ersten npx fragt es, ob ein Paket geladen werden darf — mit y bestätigen. Nach dem letzten Befehl geht Xcode von selbst auf. Ab hier wird nicht mehr getippt, nur noch geklickt.

Teil C · In Xcode

7

Sich als Entwickler eintragen

Links im Baum steht ganz oben App mit einem blauen Symbol — darauf klicken. Oben erscheinen Reiter; Signing & Capabilities wählen.

  • Automatically manage signing anhaken.
  • Bei Team Ihre Apple-ID wählen. Steht dort keine, führt Add an Account… zur Anmeldung — die gewöhnliche Apple-ID genügt, kein bezahltes Konto.

Erscheint danach ein roter Fehler zur Bundle Identifier: Hängen Sie an die Kennung etwas Eigenes an, etwa Ihren Nachnamen. Sie muss weltweit einmalig sein, und diese Fassung ist nur zum Ausprobieren.

8

Das iPad anschließen und starten

  • iPad per Kabel anstecken, entsperren, „Diesem Computer vertrauen?“ bestätigen.
  • Oben in der Mitte von Xcode steht das Ziel — dort statt eines Simulators Ihr iPad auswählen.
  • Links oben auf das ▶︎ drücken.

Beim ersten Mal dauert es. Xcode fragt womöglich nach Ihrem Anmeldekennwort, um auf den Schlüsselbund zuzugreifen — Immer erlauben.

9

Auf dem iPad Vertrauen aussprechen

Beim ersten Start meldet das iPad, dass es dem Entwickler nicht traut. Das ist normal. Auf dem iPad:

Einstellungen → Allgemein → VPN & Geräteverwaltung → Ihre Apple-ID antippen → Vertrauen.

Danach die App auf dem Homescreen starten.

Teil D · Der Befundbogen

Das ist der Zweck des ganzen Durchgangs. Bitte wirklich aufschreiben, nicht nur ansehen — beim nächsten Mal erinnert sich niemand mehr.

Flugmodus Alles abschalten, App wirklich beenden (App-Umschalter, hochwischen), neu starten. Läuft sie vollständig? Fehlt irgendwo etwas? Das ist der wichtigste Punkt — er ist das stärkste Argument gegenüber Apples Richtlinie 4.2.
Apple Pencil Wie fühlt sich das Zeichnen an? Kommt der Strich verzögert? Setzt die Spitze sauber auf?
Teilen Ein Werk sichern. Sollte gehen — die App benutzt das Teilen-Blatt, nicht den Download-Weg.
Druckbogen Der wird vermutlich nicht gehen. Die App öffnet dafür ein zweites Fenster, und das liefert im nativen Rahmen nichts zurück. Bitte trotzdem ausprobieren und notieren, was genau passiert — nichts, ein leeres Fenster, ein Absturz?
Die Galerie ist leer Das ist richtig so und kein Fehler: Für iOS ist das eine andere App als das Symbol vom Homescreen, mit eigenem Speicher.
Drehen Quer- und Hochformat, beides einmal durchspielen.

Wenn etwas schiefgeht

„command not found: npm“

Node fehlt oder das Terminal kennt es noch nicht. Von nodejs.org die LTS-Fassung installieren, Terminal schließen und neu öffnen.

Der Symbol-Schritt bricht ab

Kein Chrome auf dem Mac. Siehe den gelben Kasten bei Schritt 4.

„Signing for App requires a development team“

Schritt 7 ist noch nicht erledigt: Automatically manage signing anhaken und ein Team wählen.

„Unable to install“ oder das iPad taucht nicht auf

iPad entsperren, Kabel prüfen, „Diesem Computer vertrauen?“ bestätigt? Manchmal hilft, Xcode einmal zu beenden und neu zu starten.

Die App startet und bleibt weiß

Dann ist beim Umziehen der Dateien etwas nicht mitgekommen. Bitte in Xcode unten die Konsole ansehen und die erste rote Zeile notieren — mit der lässt sich das finden.

Nach sieben Tagen startet sie nicht mehr

Das ist so vorgesehen und kein Fehler. Mit einer gewöhnlichen Apple-ID läuft eine selbst aufgespielte App sieben Tage. Einfach in Xcode noch einmal auf ▶︎ drücken.

Was danach kommt

Erst wenn dieser Durchgang getragen hat, lohnt das Developer Program. Was dann folgt — Verträge, Bundle-ID, Bildschirmfotos, die Erklärungen in App Store Connect — steht in Bis in den Store. Was noch unentschieden ist, im Register.

Und die unbequeme Frage bleibt: Richtlinie 4.2 lehnt Anwendungen ab, die nichts weiter tun, als eine Website anzuzeigen. Dieser Durchgang beantwortet sie nicht — er liefert nur die Messwerte, mit denen sie sich beantworten lässt. Mehr dazu in der Attrappe, Abschnitt 4.

Geschrieben für den ersten Durchgang, nicht für die Einreichung. Wer unterwegs auf etwas stößt, das hier fehlt: Es gehört hierher.
